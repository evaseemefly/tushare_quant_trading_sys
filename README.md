# 申万接口——国内量化报告

基于 Tushare 的国内市场量化监测系统。项目最终规划为六个相互独立的模块，
每个模块使用一个 Python 文件，方便单独运行、调试和让其他模型参与维护。

## 当前版本：v1（已实现前两个模块）

本次只生成前两个模块，后四个模块暂不实现。

| 模块 | 文件 | v1 状态 | 主要功能 |
| --- | --- | --- | --- |
| 1. 市场广度与成交额 | `market_breadth.py` | 已实现 | 全市场成交额、量能比率、涨跌家数、20 日新高/新低、MA20/60/120 广度 |
| 2. 申万行业轮动 | `industry_rotation.py` | 已实现 | 申万一级行业 1/5/20/60 日收益、相对 A500 超额收益、成交额比率、动能和四象限 |
| 3. ETF 资金与交易质量 | `etf_quality.py`（规划） | 待开发 | ETF 成交额、份额变化、折溢价和指数跟踪偏离 |
| 4. 指数估值与历史位置 | `index_valuation.py`（规划） | 待开发 | PE、PB、股息率及 3/5 年历史分位 |
| 5. 市场风格轮动 | `style_rotation.py`（规划） | 待开发 | 大小盘、成长/宽基、红利/市场及主题相对强弱 |
| 6. 组合风险与交易条件 | `portfolio_risk.py`（规划） | 待开发 | 组合穿透、重叠敞口、回撤、风险上限和下一交易日观察条件 |

v1 的定位是“研究数据层”，输出 CSV 供后续报告和原有趋势模型使用，不直接生成买卖指令，也不会覆盖原有的仓位、冷静期和人工风险上限。

## v1 主要功能

### 1. 市场广度与成交额

`market_breadth.py` 从 Tushare `daily` 获取股票日线，按交易日汇总：

- 全市场成交额（亿元）和相对过去 20 个交易日均值的 `amount_ratio_20`；
- 上涨、下跌、平盘家数及 `up_ratio`；
- 上涨成交额占比 `up_amount_ratio`，用于识别权重股拉升或普涨；
- 基于此前 20 个交易日的真实新高、新低家数；
- 收盘价高于 MA20、MA60、MA120 的股票比例；
- MA60 广度的日变化（百分点）。

滚动均线、新高新低和成交额基准均只使用当日之前的数据，避免把当日数据泄漏到比较基准中。数据不足时输出空值，而不是用 0 伪造信号。

### 2. 申万行业轮动

`industry_rotation.py` 从 Tushare `sw_daily` 获取申万行业指数，从 `index_daily` 获取中证 A500 基准，输出最新交易日的行业轮动矩阵：

- 行业 1/5/20/60 日收益；
- 相对 A500 的 5/20/60 日超额收益；
- 成交额相对过去 5/20 日均值的比率；
- 20 日超额收益动能变化；
- “领先且改善、落后但改善、领先但减弱、落后且减弱”四象限观察标签。

四象限只用于研究和报告展示，不是自动交易信号。行业历史数据不足 60 个交易日时，相应收益或动能字段会为空。

本 v1 先使用行业指数层数据；行业成分股的上涨占比、站上 MA20 比例，以及按历史纳入/剔除日期还原成员结构，将在后续迭代接入 `index_member_all` 和个股日线。

## 安装依赖

```bash
pip install tushare pandas pyyaml
```

建议使用 Python 3.9 或更高版本。

## 配置 Tushare

在项目根目录的 `config.yaml` 中配置 token：

```yaml
keys:
  tushare: "你的 Tushare token"
```

当前配置还保留了原有策略和监控标的字段；模块 2 使用 `benchmark.a500_ts_code`，默认值为 `000510.SH`。不要把真实 token 提交到公开仓库，若 token 已经泄露，应在 Tushare 控制台及时更换。

## 运行方式

两个模块都支持独立运行，日期格式为 `YYYYMMDD`：

```bash
python market_breadth.py \
  --start-date 20260101 \
  --end-date 20260928 \
  --output market_breadth.csv

python industry_rotation.py \
  --start-date 20260101 \
  --end-date 20260928 \
  --output industry_rotation.csv
```

不传日期时，默认抓取最近约 240 个自然日。若配置文件不在脚本同目录，可通过 `--config /path/to/config.yaml` 指定。

## 输出说明

- `market_breadth.csv`：每行一个交易日，可直接用于市场总览、成交额曲线和广度曲线。
- `industry_rotation.csv`：默认每行一个申万行业，为最新交易日的轮动快照；代码调用 `calculate_rotation(..., latest_only=False)` 可取得完整历史矩阵。

Tushare 返回的 `daily.amount` 和 `sw_daily.amount` 单位是千元；模块 1 的 `total_amount_100m` 已转换为亿元，行业成交额比率不受单位影响。

## 后续开发顺序

1. 先用历史数据检查模块 1、2 的缺失值、接口权限和口径；
2. 再实现 ETF 交易质量、估值、风格和组合风险四个模块；
3. 最后把市场广度和行业轮动作为原有趋势模型的辅助过滤条件，回测误触发率、最大回撤和交易频次后，再确定交易阈值。

当前版本刻意不把“放量 20%”“连续上涨两天”等阈值写死，避免在没有历史回测前形成未经验证的交易规则。

# 国内监测报告升级方案

> 结合 9 月 24 日《多市场量化资产多周期监测报告》
>
> 建议这次升级不要简单增加更多技术指标，而是让国内报告从目前的单一指数趋势监控，升级为「市场环境 — 行业轮动 — 量价确认 — ETF 交易 — 组合风控」五个层次的决策系统。

尤其是目前国内投资主要围绕中证 A500、沪深 300、科创 50、创业板、芯片，以及红利、黄金、有色等方向，新增模块应该直接服务于这些标的的加仓、减仓和暂停交易判断。

---

## 一、先看现有报告还缺少什么

当前 v3 版本已经有较完整的中长期趋势模型，不建议推倒重来。

从附件看，目前主要包括：

| 现有功能 | 当前实现                                        |
| -------- | ----------------------------------------------- |
| 趋势判断 | EMA20、EMA60、MA120、MA250                      |
| 长期环境 | MA120 的 20 日斜率、MA250 的 40 日斜率          |
| 价格位置 | L1—L5 价格分位                                  |
| 风险测度 | ATR20、60 日价格区间                            |
| 仓位管理 | 模型仓位、执行仓位                              |
| 执行纪律 | v3 执行状态、冷静期                             |
| 监控标的 | 沪深 300、A500、创业板、科创 50、恒科、芯片 ETF |

例如 9 月 24 日报告中：

- A500 收盘 **5486.01**，低于 L1 的 **5520.27**
- 模型仓位 **100%**、执行仓位 **80%**
- 状态为 **Risk-On 第 1 日预警**
- 对应文件：`China_Index_Monitor_2026-09-24.pdf`

这其实反映了当前模型的一个关键问题：

> 它能告诉我们价格已经下跌、趋势正在恶化，但还不足以判断下跌的内部结构，以及反弹能否得到市场量能和行业广度的支持。

因此，接下来最有价值的不是增加 MACD、KDJ 一类指标，而是补足以下信息：

- 市场整体是否有资金和广度支持
- 下跌是否集中在少数权重股
- 哪些行业出现持续走强或走弱
- 指数的量价信号与 ETF 交易信号是否一致
- 现有投资组合是否已经承担过多同方向风险

## 二、建议增加的六大模块

| 优先级  | 模块               | 定位                                                         |
| ------- | ------------------ | ------------------------------------------------------------ |
| P0 必做 | 市场广度与量价确认 | 判断上涨、下跌是否得到全市场支持，以及市场是否出现内部结构改善 |
| P0 必做 | 申万行业轮动       | 判断资金活跃度与相对强弱是否向新的行业扩散，而不只是展示单日涨跌 |
| P1 重点 | ETF 资金与交易质量 | 判断指数走势和对应 ETF 是否匹配，并观察份额、成交额及折溢价  |
| P1 重点 | 指数估值与历史位置 | 将趋势判断与估值判断区分，避免将跌幅较大直接等同于低估       |
| P1 重点 | 风格轮动与相对强弱 | 追踪大盘、小盘、成长、红利之间的相对变化                     |
| P1 重点 | 组合风险与交易条件 | 汇总各标的的风险暴露、信号变化和下一交易日的观察条件         |

### 模块 1：市场广度 + 成交额（优先加入）

原本提出增加主要指数的每日成交量统计，建议升级成完整的市场量价分析。

#### 核心指标

| 指标                   | 判断意义             |
| ---------------------- | -------------------- |
| 沪深 A 股总成交额      | 全市场流动性         |
| 成交额 / 20 日均额     | 放量或缩量           |
| 上涨家数占比           | 市场参与广度         |
| 创 20 日新高、新低家数 | 市场内部强弱         |
| 站上 MA20 股票占比     | 短期广度             |
| 站上 MA60 股票占比     | 中期广度             |
| 站上 MA120 股票占比    | 中长期广度           |
| 上涨成交额占比         | 活跃成交集中在哪一侧 |

#### 特别推荐两个指标

**A. 成交额相对强度**

$$
VR_{20}=\frac{\text{今日成交额}}{\text{过去 20 日平均成交额}}
$$

建议分别计算全市场、A500、沪深 300、科创 50 的量能指标。

**B. 市场趋势广度**

$$
B_{60}=\frac{\text{收盘价高于 MA60 的股票数量}}{\text{有效样本股票数量}}
$$

同时计算 $B_{20}$ 和 $B_{120}$，形成市场广度曲线。

更关注的是 **价格、成交额和广度的组合**，而不是任何一个指标单独变化。

#### 量价分析示例（假设情景）

| 项目          | 数值  | 含义            |
| ------------- | ----- | --------------- |
| 指数涨幅      | +1.2% | 价格回升        |
| 成交额比率    | 1.25  | 相对放量        |
| 上涨家数占比  | 72%   | 参与面较广      |
| MA60 广度变化 | +5pp  | 中期结构改善    |
| 综合判断      | —     | 放量 + 广度改善 |

这样的反弹具有更广泛的市场参与，可以作为原有趋势信号的确认依据。

> 如果指数上涨，但全市场只有 25% 的股票上涨，且成交额低于 20 日均额，就需要警惕权重股拉升造成的指数失真。
>
> 这对沪深 300 和 A500 的加仓判断很有价值。

数据方面，通过 Tushare 股票日线、每日基本指标及市场成交统计可以构建这套模块。

### 模块 2：申万行业轮动，而不仅仅是热力图

热力图显示当天谁涨谁跌，但对行业 ETF 而言，更重要的是连续性。

建议在热力图后面增加一张 **行业轮动矩阵**。

#### 行业轮动四象限

|              | 动能增强                       | 动能下降                   |
| ------------ | ------------------------------ | -------------------------- |
| **相对强势** | 领先且改善<br>重点观察趋势延续 | 领先但减弱<br>留意趋势衰减 |
| **相对弱势** | 落后但改善<br>观察是否形成轮动 | 落后且减弱<br>关注风险持续 |

这是观察框架，不是自动买卖信号。

- 相对强弱：行业相对于 A500 的表现
- 动能变化：相对强弱的近期变化

#### 每日跟踪 31 个申万一级行业

| 行业指标               | 时间维度                 |
| ---------------------- | ------------------------ |
| 涨跌幅                 | 1 日、5 日、20 日、60 日 |
| 相对于 A500 的超额收益 | 5 日、20 日、60 日       |
| 成交额比率             | 5 日、20 日              |
| 行业内上涨股票占比     | 每日                     |
| 行业内站上 MA20 比例   | 每日                     |
| 相对强弱变化           | 5 日、20 日              |

这样就能观察一个行业究竟是单日反弹，还是正在形成连续的相对强势。

行业指数可通过 `sw_daily` 获取，行业成员可通过 `index_member_all` 获取。后者包含成分股纳入和剔除日期，便于正确还原历史行业结构。

尤其建议将 **半导体、电子、有色、贵金属、银行、公用事业** 作为常驻观察方向，与现有投资组合形成联系。

### 模块 3：ETF 资金与交易质量

这个模块需要把指数与具体 ETF 分开。

- 指数反映资产表现
- ETF 还有自身的成交、流动性和份额变化

例如分析芯片时：底层指数提供行业趋势，而 `512760` 还需要独立观察 ETF 成交额、跟踪表现及交易质量。

| 指标                 | 实际用途         |
| -------------------- | ---------------- |
| ETF 每日成交额       | 判断交易活跃度   |
| ETF 成交额 MA20      | 衡量量能是否异常 |
| 份额 5 日、20 日变化 | 观察申赎方向     |
| 份额变化 × 参考净值  | 估算净申赎规模   |
| 折溢价率             | 避免异常价格成交 |
| ETF 相对指数偏离     | 观察跟踪表现     |

注意：

- ETF 二级市场成交额 **不等于** 新增资金流入
- 份额增加也 **不一定** 意味着投资者马上获利
- ETF 份额变化更适合判断一级市场申赎
- 成交额则反映二级市场活跃度

Tushare 目前提供 `fund_daily`、`fund_share` 和 `fund_nav` 等接口。更完整的每日 ETF 份额、规模及净值接口 `etf_share_size` 要求 8000 积分，且上一交易日数据通常要到次日上午更新。

因此，第一阶段无需为了这个模块额外升级权限。可以先获取已有份额数据，正式报告中注明数据日期。

### 模块 4：指数估值与历史位置

当前报告中的价格分位已经能回答「价格在近期什么位置」，但尚不能回答「估值在历史什么位置」。

建议将两者并列，避免混为一谈。

| 指数      | 建议估值指标               |
| --------- | -------------------------- |
| 沪深 300  | PE、PB、股息率             |
| 中证 A500 | PE、PB、股息率             |
| 科创 50   | PE、PB、盈利指标有效覆盖率 |
| 创业板指  | PE、PB                     |
| 中证红利  | 股息率、PB                 |

建议使用近 3 年和近 5 年历史分位，而不是只看当前估值。

对于科创 50 等高成长指数，需要特别注意亏损企业及盈利波动带来的 PE 失真，因此 PB 和盈利覆盖情况应同时展示。

这个模块的作用是回答：

> 当前便宜究竟只是因为股价下跌，还是估值本身已经回到相对较低的位置。

估值可以成为趋势模型的辅助信息，但不应该因为估值低就自动覆盖已有风险信号。

Tushare 的 `daily_basic` 支持股票估值与市值数据，部分宽基还可使用 `index_dailybasic`，不过该指数接口覆盖范围有限。A500、科创 50 等未覆盖标的需要用可获得的指数公司数据或按成分股计算，并统一估值方法。

### 模块 5：市场风格轮动

这个模块专门解决另一个问题：即使市场整体走弱，不同指数和风格也可能处于完全不同的阶段。

例如 A500、科创 50 和红利指数同时下跌，但相对强弱可能已经明显分化。

建议建立四组相对强弱指标：

| 风格对比             | 重点观察         |
| -------------------- | ---------------- |
| 中证 1000 / 沪深 300 | 小盘与大盘       |
| 科创 50 / A500       | 成长与宽基       |
| 中证红利 / A500      | 防御与市场整体   |
| 半导体行业 / A500    | 科技行业相对强弱 |

最有价值的是相对强弱比值的 **20 日和 60 日趋势**，而不是单日谁涨得多。

对于红利类基金，这个模块尤为重要：当市场调整时，红利是否真正表现出相对抗跌性？还是与宽基一起持续下跌？

同时，还可以把黄金股、有色金属、公用事业等与持仓相关的行业纳入，形成一张风格强弱监测图。

---

### 模块 6：组合风险与交易条件

这是新系统最终落地的地方。

现有报告的第二页已经展示了模型仓位、执行仓位和冷静期，但它们主要是各资产独立计算的结果，尚没有充分体现资产之间的重叠风险。对应文件：`China_Index_Monitor_2026-09-24.pdf`。

例如 A500、沪深 300、科创 50 和芯片 ETF 之间存在不同程度的成分与行业敞口重叠。

如果分别看信号，很容易低估组合实际承担的成长和科技风险。

建议增加一个组合穿透模块：

| 风险项目       | 监控方式               |
| -------------- | ---------------------- |
| 国内权益总敞口 | 市值汇总               |
| 单一主题敞口   | 主题基金及相关重叠部分 |
| 科技成长风险   | 科创、芯片等综合暴露   |
| 红利防御仓位   | 国内红利与港股红利     |
| 当前组合回撤   | 相对历史净值高点       |
| 未来加仓额度   | 目标仓位减当前仓位     |

这项功能还应区分「模型允许的仓位」和「实际愿意承担的仓位」，保留人工设置的风险上限，避免模型连续发出加仓信号时突破组合纪律。

## 三、把六大模块整合为真正的交易决策

最重要的不是让模型给每个指数打更多分，而是让它回答明确的问题。

例如，A500 出现连续下跌后，想知道能否重新开始分批建仓时，应同时检查：

### A500｜交易条件监控示意

> 以下为模型输出格式示例，并非 2026 年 9 月 28 日的实时信号。

| 维度       | 状态         | 观察要点                                             |
| ---------- | ------------ | ---------------------------------------------------- |
| 价格趋势   | 待修复       | 收盘价是否重新回到关键格位、EMA20 及相关趋势确认水平 |
| 成交额确认 | 待验证       | 反弹是否伴随全市场及 A500 有效放量                   |
| 市场广度   | 待验证       | 上涨家数、站上 MA20 / MA60 股票比例是否持续改善      |
| 行业参与度 | 持续观察     | 反弹是否从少数权重板块扩散至更多行业                 |
| 组合风险   | 人工上限约束 | 当前仓位是否允许增加风险敞口                         |

**输出：下一交易日的观察条件**

列出尚未满足的确认条件、对应价格水平及量能变化，不直接因为一个单独指标改善而覆盖原有风控规则。

具体阈值不建议现在直接写死，例如「成交额必须放大 20%」「连续两天上涨就买入」等。这些初始条件应利用历史数据回测，分析误触发率、最大回撤和交易频次后再固定。

## 四、最终报告应该怎样排版？

不要把所有内容塞进现有的每个指数走势图中，而是保留原来的六个标的技术分析页面，在前面插入几页具有决策价值的总览。

| 页码   | 内容                   | 作用               |
| ------ | ---------------------- | ------------------ |
| P1     | 封面                   | 日期与数据状态     |
| P2     | 市场总览及交易条件     | 一眼看懂今日状态   |
| P3     | 全市场成交额与市场广度 | 判断反弹或下跌质量 |
| P4     | 申万行业热力图         | 市场结构           |
| P5     | 行业轮动矩阵           | 持续强弱           |
| P6     | 指数及 ETF 量价统计    | 加减仓辅助         |
| P7     | 风格相对强弱           | 宽基、成长、红利   |
| P8     | 估值与组合风险         | 中期配置           |
| P9—P14 | 原有六个标的技术分析   | 保留完整趋势模型   |

这样报告会从目前 8 页扩展到 14 页左右，但原来的技术分析模型几乎无需重写。

特别希望新增的 **P2** 具有较强的摘要能力：当天哪些资产出现了新信号、哪些尚未满足确认条件、风险暴露发生了什么变化，全部集中在一张表中。

## 五、数据源与开发顺序

考虑到准备购买 Tushare 5000 积分，第一版完全可以先不增加额外的数据费用。

| 模块             | 主要数据源                    | 5000 积分方案      |
| ---------------- | ----------------------------- | ------------------ |
| 市场广度         | `daily` + `daily_basic`       | 可实现             |
| 指数量价         | `index_daily`                 | 可实现             |
| 行业热力图       | `sw_daily`                    | 可实现             |
| 行业内部广度     | `index_member_all` + 个股日线 | 可实现             |
| ETF 成交统计     | `fund_daily`                  | 可实现             |
| ETF 份额         | `fund_share`                  | 可获取已有份额记录 |
| ETF 每日完整规模 | `etf_share_size`              | 需 8000 积分       |
| 行业资金流向     | `moneyflow_ind_dc`            | 需 6000 积分       |

资金流向接口的数据本身也存在统计口径差异，不宜直接视为真实净申购资金。第一版可先用成交额、行业相对强弱、市场广度代替。

另外，建议保留盘后正式版和次日补全机制。ETF 份额、净值和申赎规模有时无法在当天报告生成时完整获取，不应该用上一交易日的数据冒充当日数据。

### 开发优先级

#### 第一期：直接提升交易判断

优先开发：

1. 市场广度
2. 成交额统计
3. 申万行业热力图
4. 行业轮动矩阵

这四部分可以共享个股日线和行业分类数据，开发效率较高。

#### 第二期：贴合个人持仓

后续增加：

1. ETF 份额
2. 风格相对强弱
3. 估值分位
4. 组合风险穿透

#### 第三期：模型验证

历史回测：将市场广度和成交额作为原 v3 模型的辅助过滤条件，检验是否减少无效加仓、降低回撤。

## 六、需要同步解释的仓位口径问题

9 月 24 日的报告显示：6 个监控资产中没有资产处于上涨趋势，但汇总模型仓位仍然达到 **92%**、执行仓位 **80%**。对应文件：`China_Index_Monitor_2026-09-24.pdf`。

这未必是计算错误，因为长期趋势标签与价格格位模型可能采用不同的逻辑，但应该在报告中解释清楚。

新增市场广度与量价确认后，尤其需要区分：

1. 长期配置仓位
2. 技术交易仓位
3. 人工风控上限

## 最终目标

最终目标不是让量化模型每天告诉你必须买什么，而是让它在准备买入 A500、科创 50、芯片或红利时，清楚展示：

- 价格是否满足条件
- 市场是否配合
- 行业是否改善
- 风险预算是否充足

这比单纯增加技术指标或热力图，对现有交易体系的帮助更大。
